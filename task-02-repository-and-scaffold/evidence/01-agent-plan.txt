## 1. Summary of Understanding

- **Business & User Context:**
  Nit's Cut is a fictional Nigerian bespoke men's tailoring business making native wear, trousers, and shirts. It serves everyday mobile web users (ages 16+) on Nigerian mobile networks where connectivity can be unstable. The application's core job is providing dependable visibility into garment order stages, revised fitting/collection dates, and recorded payments.
  
- **Task 2 Scope Boundary (Strictly Minimal):**
  We are building ONLY the project setup and a minimal home screen inside a dedicated `app/` folder. We are NOT building database schemas, tables, authentication, booking flows, or the full tailoring product at this step. The database (SQLite via `better-sqlite3` with raw SQL prepared statements and versioned migrations) and database-writing form are deliberately deferred to Step 6 of Task 2.

- **Design System Integration:**
  The scaffold must consume the Task 1 tokens (`nc-tokens.css`: colours, typography, shadows) and the Task 2 layout tokens (`nc-layout-tokens.css`: spacing, radii, layout max-widths). All UI elements must use semantic colour roles (`--nc-color-*`), typography styles (`--nc-type-*`), and layout tokens (`--nc-space-*`, `--nc-radius-*`). No hardcoded styling values (raw hex, arbitrary rem/px margins or paddings) are allowed in component styles.

## 3. Stated Assumptions & Verifications

1. **Node.js Environment:**
   - *Assumption:* The host machine has a modern Node.js runtime supporting `--watch` and standard Express 4/5.
   - *What was checked:* `node -v` previously reported `v24.16.0`, which fully supports Node.js `--watch` and modern ES/CommonJS features without needing external dev-dependencies like `nodemon`.
2. **Database Deferral:**
   - *Assumption:* `better-sqlite3` does not need to be installed or initialized in `package.json` during this initial scaffold step.
   - *Reasoning:* Step 1 and Step 2 of Task 2 explicitly restrict the initial scaffold to project setup and a minimal home screen. Adding the database and its dependencies in Step 6 provides a clean commit and clear evidence progression.
3. **Static File Hosting:**
   - *Assumption:* Bundling the static CSS tokens and fonts into `app/public/` is cleaner and more robust than mounting directories outside `app/` via Express static routes, as it makes `app/` self-contained and reproducible on any machine.
4. **Theme Mode:**
   - *Assumption:* The minimal home screen defaults to Dark mode (`data-theme="dark"` on `<html>`), consistent with the Task 1 primary presentation, while maintaining full token compatibility with Light mode (`data-theme="light"`).
5. **Port Configuration:**
   - *Assumption:* Port `3000` is the default port, but `process.env.PORT` is respected so that Step 5's deliberate port conflict experiment can easily override or conflict with this port.
