======================================================================
SECURITY ANALYSIS & HARDWARE CONTEXT
======================================================================
1. The Inversion:
   - For our application, evaluating Argon2id once during an authentication request costs ~23 ms
     of elapsed wall-clock time, which is acceptable for a user waiting on network round-trips.
   - For an attacker attempting offline password recovery against a stolen database,
     every candidate guess requires dedicating both repeated compute passes and a substantial
     64 MiB memory buffer, multiplying the resource cost of each tested password.

2. Hardware & Architecture Context:
   - This benchmark measures sequential execution on a general-purpose host CPU with p=4.
   - An attacker's actual guessing throughput depends heavily on their hardware architecture
     (such as GPU clusters, FPGAs, or custom ASICs) and optimized cracking implementations.
   - However, Argon2id's 64 MiB memory requirement creates a significant physical memory footprint
     per worker, making concurrent guesses far more hardware-intensive than for memory-free
     algorithms like SHA-256, which can run millions of instances in parallel with negligible RAM.
   - These resource requirements represent a real server cost: authentication capacity is finite,
     reinforcing why backend rate limiting and boundary controls (Step 8) are necessary.
